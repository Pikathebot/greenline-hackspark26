# 06: Fixture repo spec: `ledger-core`

`backend/fixtures/ledger-core/` is a **real, tiny Python package** with pytest + ruff. It has a green
`main` and six `case/*` branches, each carrying one genuine defect. The sandbox runs real tests
against it, and every verdict is a consequence of real execution.

It is generated by `backend/scripts/seed_repo.py`:
- Idempotent: if all six branches exist, do nothing. `--force` rebuilds.
- No network needed.
- Writes files with `\n` line endings, commits as `Greenline Seed <seed@local>`.
- The directory is gitignored in the outer repo, because it's generated.

## The six branches (each off `main`, one commit each)

### `case/0142-flaky-settlement`: flaky (hero)
- **Change:** `settlement.py` gains `import os`. At the top of `reconcile_settlement`:
  `if os.urandom(1)[0] < 77: raise TimeoutError(f"settlement reconciliation exceeded timeout={timeout}s")`.
  77/256 ≈ **30%** failure per fresh process. A docstring note explains it simulates
  load-dependent timeouts. Each sandbox run is a new container and process, so the distribution is
  genuinely random.
- **Commit message:** "settlement: add timeout guard for EOD reconciliation".
- **Expected:** reruns of the test node show a mixed distribution (P(all 10 pass) ≈ 2.8%). The fix
  target would be `tests/test_settlement.py` (e.g. retry/skip decorators), which is **protected**,
  so the run escalates.

### `case/0144-flaky-repeat`: flaky, same shape, different surface
- **Change:** new `ledger_core/payout.py` with `reconcile_payout(entries, timeout=0.5)` using the
  **same** `os.urandom` < 77 guard (raising `TimeoutError("payout reconciliation exceeded …")`).
  New `tests/test_payout.py::test_payout_reconciles_at_eod` (+42.0 / −42.0).
- **Why:** the text differs from #0142 but the root-cause shape is the same, so memory retrieval has
  to work on semantic similarity, not identical strings.
- **Expected:** triage recalls #0142 (similarity ≥ 0.82, same class), so the Reproducer is skipped
  and the run escalates on `protected_file` (`tests/test_payout.py`).

### `case/0139-dep-pin`: dependency
- **Change:** `vendor/http_util.py` renames `class Retry` → `class RetryPolicy`. The docstring says
  "simulated dependency bump renamed Retry". `http_client.py` is **not** updated.
- **Commit message:** "vendor/http_util: bump — Retry renamed to RetryPolicy".
- **Expected:** `ImportError: cannot import name 'Retry'` at test collection, deterministic. The fix
  is in `ledger_core/http_client.py`: import and use `RetryPolicy`. Green, then PR.

### `case/0137-regression`: regression
- **Change:** in `rollup.py` **only the operator**: `txn_date < end` → `txn_date <= end`. **Leave the
  docstring saying "end is exclusive"**, because real regressions rarely update the docs.
- **Commit message:** "rollup: include boundary day in settlement window".
- **Expected:** `test_reconcile_window_boundary` fails deterministically. The Patcher sees the
  breaking diff and the test, so it flips the operator back. Green, then PR.

### `case/0131-lint`: lint (tool-fixable by design)
- **Change:** `routes.py` gains an **unused `import json`** (F401), and the import block is
  **unsorted** (I001), e.g. `from typing import Any` placed before `import os` / `import json`.
  Tests still pass.
- **Commit message:** "routes: add JSON helpers (WIP)".
- **Expected:** ruff fails with F401 + I001. `ruff check --fix ledger_core/routes.py` resolves
  **both**, so the patch has 0 model calls, then green, then PR.
- **Acceptance check at seed time:** on a scratch copy, `ruff check --fix` and then `ruff check .`
  must exit 0. If F401's fix is classified unsafe in the installed ruff version, use
  `--unsafe-fixes` in `sandbox.ruff_fix` and note it.

### `case/0128-env-drift`: env
- **Change:** new `tests/test_env.py::test_region_config_present` reads
  `os.environ["LEDGER_REGION"]` and asserts it's one of `{"us-east","us-west","eu-west"}`.
- **Commit message:** "tests: assert deployment region is configured".
- **Expected:** `KeyError: 'LEDGER_REGION'`, deterministic. The sandbox environment is empty *by
  design* (`no_creds`). There's no safe code fix (hardcoding a region masks a deploy-config gap), so
  the run escalates. With the **Tight** budget it ends `budget_exhausted` during reruns.
