**`src/api/stream.ts`**, the only `EventSource` user (`docs/08` §2):
```ts
export interface StreamHandlers {
  onEvent(e: GreenlineEvent): void
  onReset(): void          // before each reopen: caller clears state, server resends full prefix
  onReconnecting(attempt: number): void
  onGiveUp(): void         // after 5 failed reopen attempts
}
export interface StreamDeps {
  EventSourceImpl?: typeof EventSource      // tests inject a fake
  setTimeout?: (fn: () => void, ms: number) => unknown
  clearTimeout?: (h: unknown) => void
}
export const RECONNECT_DELAY_MS = 1000
export const MAX_RECONNECTS = 5
export function openRunStream(runId: string, h: StreamHandlers, deps?: StreamDeps): { close(): void }
```
Behaviour:
1. `new EventSourceImpl(\`/api/runs/${runId}/stream\`)`.
2. `onmessage`: `JSON.parse(msg.data)`; parse failure → `console.warn` and ignore. Call
   `h.onEvent(e)`. Reset `attempts = 0` on any successfully parsed event. If `e.type === 'done'`:
   **`es.close()` immediately**, mark finished, no more handlers fire.
3. `onerror` while not finished and not closed by the caller: `es.close()`; `attempts++`;
   if `attempts > MAX_RECONNECTS` → `h.onGiveUp()` and stop; else `h.onReconnecting(attempts)`,
   then after `RECONNECT_DELAY_MS` call `h.onReset()` and open a new EventSource (back to 1).
4. `close()`: closes the current EventSource, cancels a pending reopen timer, and makes every
   later callback a no-op.

**`src/state/runStore.ts`**
```ts
export type RunStatus = 'idle' | 'starting' | 'streaming' | 'done' | 'error'
export type Connection = 'none' | 'open' | 'reconnecting' | 'lost'
export interface RunProblem { kind: 'conflict' | 'not_found' | 'unreachable' | 'http' | 'stream'
                              message: string }
interface RunStoreState {
  status: RunStatus; connection: Connection; runId: string | null
  events: GreenlineEvent[]      // debugging only; render from `state`
  state: RunState               // reduce() output, the ONLY run data components read
  problem: RunProblem | null    // why a start/stream failed (A9 turns it into toasts/banners)
  startRun(caseId: string, opts: StartRunOptions): Promise<void>
  attach(runId: string): void
  receive(e: GreenlineEvent): void
  reset(): void
}
export function createRunStore(deps: {
  api: Pick<Api, 'startRun'>
  openStream: typeof openRunStream
  onRunDone: () => void          // app wiring: useCaseStore.getState().refresh()
})
export const useRunStore = createRunStore({ api, openStream: openRunStream,
  onRunDone: () => void useCaseStore.getState().refresh() })
```
Semantics:
- `startRun`: if `status` is `starting` or `streaming` → no-op (one GPU, one run). Set
  `status: 'starting'`, `problem: null`. `await api.startRun`. On success `attach(runId)`. On
  `ApiError`: 409 → `problem {kind:'conflict', message:'A run is already in progress'}`; 404 →
  `not_found` with `detail`; 0 → `unreachable`; else `http`. Status back to `idle`
  (or the previous `done`).
- `attach(runId)`: close any current stream handle (kept in a closure variable, not in state);
  set `runId`, `events: []`, `state: EMPTY_STATE`, `status: 'streaming'`, `connection: 'open'`,
  `problem: null`; `openStream(runId, handlers)`:
  - `onEvent` → `receive(e)`, and set `connection: 'open'` if it was `reconnecting`.
  - `onReset` → `events: []`, `state: EMPTY_STATE` (the server resends the full prefix).
  - `onReconnecting` → `connection: 'reconnecting'`.
  - `onGiveUp` → `status: 'error'`, `connection: 'lost'`,
    `problem {kind:'stream', message:'Lost the run stream after 5 retries'}`.
- `receive(e)`: `events: [...events, e]`, `state: reduce(state, e)`. If `e.type === 'done'`:
  `status: 'done'`, `connection: 'none'`, then call `onRunDone()`. (An `error` event does not
  change `status`; the run still ends with `done{outcome:'error'}`.)
- `reset()`: close the stream; back to initial (`idle`, `none`, `null`, `[]`, `EMPTY_STATE`, `null`).

## Tests (Vitest, `environment: 'node'`, no DOM library)
**`src/api/stream.test.ts`**: a `FakeEventSource` class (records instances, `close()` flag,
helpers `emit(obj)` → calls `onmessage({data: JSON.stringify(obj)})`, `fail()` → `onerror()`),
and `vi.useFakeTimers()` passed via `deps.setTimeout/clearTimeout` (or the global fakes).
1. Opens `/api/runs/<id>/stream`; parsed events reach `onEvent` in order.
2. A `done` event closes the EventSource; later `emit`/`fail` on it trigger nothing.
3. `fail()` before `done` → `onReconnecting(1)`, old source closed; after 1000 ms `onReset` is
   called, then a new FakeEventSource exists.
4. Five failures in a row reopen five times; the sixth → `onGiveUp`, no new instance.
5. A successfully parsed event resets the attempt counter (fail, reopen, emit, fail → `onReconnecting(1)` again).
6. `close()` during the 1 s wait cancels the reopen.
7. Malformed `data` is ignored (no throw, no `onEvent`).

**`src/state/runStore.test.ts`**: fake `api.startRun`, fake `openStream` capturing the handlers,
`onRunDone` spy. Feed events from `ALL_SEQUENCES` (`__fixtures__/sequences.ts`, A1).
1. `startRun` → status `starting` then `streaming`, `openStream` called with the returned runId.
2. Feeding `HERO_0142` through `onEvent` → `state` equals `reduceAll(HERO_0142)`, `events`
   length matches, status `done`, connection `none`, `onRunDone` called exactly once.
3. `startRun` while `streaming` is a no-op (`api.startRun` not called again).
4. `ApiError(409)` → `problem.kind === 'conflict'`, status `idle`, no stream opened.
5. `ApiError(0)` → `unreachable`; `ApiError(404, 'no recorded demo run…')` → `not_found` with that message.
6. `onReset` mid-run clears `events` and `state` to `EMPTY_STATE`; replaying the full sequence

7. `onReconnecting` → `connection: 'reconnecting'`; the next `onEvent` → `open`.
8. `onGiveUp` → status `error`, connection `lost`, `problem.kind === 'stream'`.
