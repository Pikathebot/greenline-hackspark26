## Keyboard (`src/app/useKeyboard.ts`)

```ts
export type KeyActionName = 'selectCase' | 'run' | 'toggleBudget' | 'toggleMode' | 'toggleScoreboard'
  | 'download' | 'escape' | 'toggleDebug' | 'none'
export interface KeyContext {
  caseIds: string[]                       // ids the backend listed
  selectedId: string | null
  status: RunStatus                       // runStore status
  reachable: boolean | null               // healthStore.backendReachable
  hasReport: boolean                      // state.report !== null && state.outcome !== null
  selectedHasDemoRun: boolean             // for D: don't switch to Recorded when unavailable
  mode: RunMode
  scoreboardOpen: boolean; debugOpen: boolean
}
export interface KeyEventLike { key: string; code: string; ctrlKey: boolean; metaKey: boolean; altKey: boolean
  repeat: boolean; target: { tagName?: string; isContentEditable?: boolean } | null }
export const CASE_KEY_ORDER = ['0142','0144','0139','0131','0137','0128'] as const
export function keyAction(e: KeyEventLike, ctx: KeyContext): { name: KeyActionName; caseId?: string }
```
Rules (`keyAction`), in order:
1. `none` if `e.ctrlKey || e.metaKey || e.altKey || e.repeat`, or the target is an `input`, `textarea`, `select` or content-editable.
2. `e.code === 'Backquote'` → `toggleDebug`.
3. `Escape` → `escape`.
4. `1`-`6`: `caseId = CASE_KEY_ORDER[n-1]`; if `ctx.caseIds` includes it → `{selectCase, caseId}` else `none`. Ignored while a run is `starting`/`streaming` (selecting another case mid-run would desync the header from the run) → `none`.
5. `Enter` or `r`/`R` → `run` **only if** `reachable !== false`, `selectedId !== null`, `status` not `starting`/`streaming`; otherwise `none`.
6. `t`/`T` → `toggleBudget`; `d`/`D` → `toggleMode`, except `none` when the current mode is `live` and `!selectedHasDemoRun` (can't switch to Recorded). Both `none` while a run is in progress.
7. `s`/`S` → `toggleScoreboard`.
8. `e`/`E` → `download` only if `hasReport`, else `none`.
9. everything else → `none`.

Hook (`useKeyboard`): one `useEffect`, listener on `window`; on each event build `KeyContext` from `useUiStore.getState()`, `useCaseStore.getState()`, `useRunStore.getState()`, `useHealthStore.getState()` (read at event time, no re-subscribing); call `keyAction`; if `name !== 'none'` call `e.preventDefault()` (so `Enter` on a focused button can't also click it) and execute:
- `selectCase` → `uiStore.selectCase(id)`
- `run` → `runStore.startRun(selectedId, { mode, budget })`
- `toggleBudget` / `toggleMode` → the existing uiStore toggles
- `toggleScoreboard` → `uiStore.setScoreboardOpen(!open)`
- `download` → `downloadReport()` (below)
- `escape` → if `scoreboardOpen` → close it; else if `debugOpen` → `toggleDebug()`; else nothing
- `toggleDebug` → `uiStore.toggleDebug()`
`downloadReport()` is a small exported function in `src/components/ArtifactPane.tsx`'s sibling `src/app/download.ts` (`triggerDownload(filename, text)`: `Blob` → `URL.createObjectURL` → temporary `<a download>` click → `revokeObjectURL`; guarded to run only in a browser). Both the hook and the button call it with `buildReportMarkdown(...)` output.

## Notices (`src/view/notices.ts`, `Banner.tsx`)

```ts
export interface NoticeView { title: string; sub: string; tone: 'danger' | 'warn'; autoDismiss: boolean }
export function noticeView(p: { reachable: boolean | null; connection: Connection; problem: RunProblem | null;
                                runError: string | null; status: RunStatus }): NoticeView | null
```
Priority (first match wins; one banner at a time):
1. `reachable === false` → danger: title `Backend offline: start uvicorn on :8000`, sub `Retrying every 3 s. Nothing below is live until it answers.` (existing text)
2. `connection === 'reconnecting'` → warn: title `Reconnecting to the run stream…`, sub `The server replays the whole run once the link is back.`
3. `problem?.kind === 'stream'` → danger: title `Lost the run stream`, sub `${problem.message}. Press Enter to run again.`
4. `problem?.kind === 'conflict'` → warn, `autoDismiss: true`: title `A run is already in progress`, sub `Wait for it to finish, then run again.`
5. `problem?.kind === 'not_found'` → danger: title `Can't start that run`, sub `problem.message`
6. `problem?.kind === 'unreachable' | 'http'` → danger: title `Couldn't start the run`, sub `problem.message`
7. `runError` → danger: title `Run error: ${runError}`, sub `The run ended with outcome error.` (existing text)
8. otherwise `null`.
`Banner.tsx`: reads `healthStore.backendReachable`, `runStore.connection/problem/status/state.error`; renders `.banner` with the `Warn` icon, title, `.sub`; tone `warn` → `style={{background:'var(--warn)',color:'var(--on-warn)'}}`. When `autoDismiss`, a `useEffect` keyed on the notice calls `runStore.clearProblem()` after **6 s** (clear the timeout on unmount/change). `runStore.clearProblem` is the only new store code.
Recovery behaviour to verify (already true in A3, just don't break it): after `status:'error'` the Run button is enabled again and a new run resets state; `bootstrap` re-attaches to an active run after a refresh.
